=== WIS2 Node Assessment Process

Data publishers are required to demonstrate that their WIS2 Node implementation meets the requirements of the WIS2 specification as part of the "WIS2 Node Assessment Process".

The WIS2 Node Assessment Process is initiated whenever an authorized data publisher submits a WIS2 Node registration request to the WMO Secretariat.

Global Information System Centres (GISCs) are responsible for assessing WIS2 Node implementations in their Area of Responsibility (AoR) and providing feedback to the WMO Secretariat.

For an overview GISCs and their AoRs, see https://community.wmo.int/site/knowledge-hub/programmes-and-initiatives/wmo-information-system-wis/wis-centres-ncs-dcpcs-and-giscs[WMO: WIS centres (NCs, DCPCs, and GISCs)] on the WMO Knowledge Hub.

==== Roles and Responsibilities

Prior to the WIS2 Node Assessment process, the WMO Secretariat will ensure the centre-id is published in the WMO Codes Registry at https://codes.wmo.int/wis/topic-hierarchy/_centre-id

During the WIS2 Node assessment:

- The WMO Secretariat connects the WIS2 Node to the WIS2-dev environment.
- The GISC in the data publisher's AoR performs the assessment.
- The GISC informs the WMO Secretariat when the assessment is completed.

[NOTE]
.Optional pre-registration testing
====
Data publishers and commercial WIS2 solution providers who want to test their systems before registration can contact the WMO Secretariat at wis2-support@wmo.int to request that a test system be connected to WIS2-dev.
====

==== WIS2 Development Environment

The WIS2 Development environment (WIS2-dev) consists of:

- A Global Broker with a publicly accessible MQTT endpoint available at: `mqtts://gb.wis2dev.io:8883`
- A Global Discovery Catalogue with an OGC API - Records endpoint available at: `https://gdc.wis2dev.io/`
- A Global Cache provided through Amazon S3 web services

==== WIS2-dev Global Broker

When a new WIS2 Node registration request is received from an authorized data publisher, the WIS2-dev Global Broker is configured with a new subscription to the MQTT endpoint provided by the data publisher.

The new subscription on the WIS2-dev Global Broker will subscribe to the topic:

- `origin/a/wis2/&lt;centre-id&gt;/#`

where `&lt;centre-id&gt;` is the unique identifier of the WIS2 Node.

The WIS2-dev Global Broker republishes all valid WIS2 Notification Messages. A message is considered invalid when:

- the channel does not match the WIS2 Topic Hierarchy, or
- the message does not conform to the WIS2 Notification Message specification, or
- the message is a data-notification for which no corresponding metadata record can be found in the WIS2-dev Global Discovery Catalogue.

==== WIS2-dev Global Cache and Global Discovery Catalogue

The WIS2-dev Global Cache downloads data advertised in data notifications published on:

- `origin/a/wis2/&lt;centre-id&gt;/data/core/#`
- `origin/a/wis2/&lt;centre-id&gt;/metadata/#`

No download attempt is made if the data has already been downloaded, unless the download link indicates `rel="update"`.

After a successful download, the WIS2-dev Global Cache publishes a data-notification on `cache/a/wis2/&lt;centre-id&gt;/#`, with the full topic matching that of the original WIS2 Node, but with `origin` replaced by `cache`.

Notifications published by the WIS2-dev Global Cache on `cache/a/wis2/#` are republished by the WIS2-dev Global Broker.

The WIS2-dev Global Discovery Catalogue subscribes to the WIS2-dev Global Broker at `cache/a/wis2/&lt;centre-id&gt;/metadata` and validates metadata records published by the WIS2 Node using the pywcmp validation and quality assessment tool.

==== Assessment Preparation for Data Publishers

Before the assessment, data publishers should ensure that:

- The WIS2-dev IP address, `52.25.203.140`, is allowlisted for the HTTP and MQTT ports used by the WIS2 Node.
- The WIS2 Node can publish data notifications for metadata, and the published metadata contains a valid WCMP2 record.
- The WIS2 Node can publish data notifications for data, and the data notifications match the published metadata.

=== GISC test setup instructions

GISCs subscribe to `mqtts://gb.wis2dev.io:8883` using username/password `everyone/everyone` and set up a connection to the topics:

- `origin/a/wis2/&lt;centre-id&gt;/#`
- `cache/a/wis2/&lt;centre-id&gt;/#`
- `monitor/a/wis2/&lt;centre-id&gt;`

GISCs will coordinate with the contact point for the new WIS2 Node to publish metadata for their datasets first and then to publish data notifications.

Approximately 30 minutes are needed after metadata is published before the Global Broker can validate that published data has corresponding metadata.

GISCs will follow up on errors reported on the monitor topic and assist the contact point of the new WIS2 Node with corrective actions.

==== Assessment Completion Checklist

The WIS2 Node Assessment is considered complete when:

- One or more metadata records are available for the WIS2 Node when searching `https://gdc.wis2dev.io/collections/wis2-discovery-metadata/items?q=%3Ccentre-id%3E`
- MQTT notifications seen on WIS2-dev GB at `origin/a/wis2/&lt;centre-id&gt;/metadata`
- MQTT notifications seen on WIS2-dev GB at `origin/a/wis2/&lt;centre-id&gt;/data/#`
- MQTT notifications seen on WIS2-dev GB at `cache/a/wis2/&lt;centre-id&gt;/metadata`
- MQTT notifications seen on WIS2-dev GB at `cache/a/wis2/&lt;centre-id&gt;/data/core/#`

==== Common Assessment Issues

[cols="2,3",options="header"]
|===
|Issue
|Recommended action

|Notifications published under `origin/a/wis2/&lt;centre-id&gt;` by the WIS2 Node are not being republished by the WIS2-dev Global Broker.
|The WIS2-dev Global Broker will only republish notifications adhering to WIS2 standards. Messages reusing a previously used 'id' will be discarded as duplicates. Ensure that you use a valid WIS2 topic for the MQTT channel, that the payload adheres to the WIS2 Notification Message standard, and that a unique 'id' is used for each notification.

|Canonical URL embedded in a WIS2 data-notification is not accessible from WIS2-dev
|Ensure that the canonical URL is reachable from the WIS2-dev environment over the public internet. Check that the DNS resolves to the correct IP address and that the WIS2-dev incoming IP address, `52.25.203.140`, is allowlisted.

|WIS2 Node is not publishing data notifications for metadata
|Ensure that data notifications for metadata are being published every 24 hours on the topic `origin/a/wis2/&lt;centre-id&gt;/metadata` and that the notification contains a valid WCMP2 record in the data payload.

|Publishing a metadata-notification results in a notification on `origin/a/wis2/&lt;centre-id&gt;/metadata` but does not result in a notification on `cache/a/wis2/&lt;centre-id&gt;/metadata` on the WIS2-dev Global Broker
|Updated metadata records are rejected by the WIS2-dev Global Cache if a previous record with the same data-id was already cached and the download link did not indicate rel="update". Ensure that the download link for updated metadata records indicates rel="update".

|Metadata records published by the WIS2 Node are cached by the WIS2-dev Global Cache, but rejected by the WIS2-dev Global Discovery Catalogue
|The WIS2-dev Global Discovery Catalogue will reject data that fails the pywcmp validation and quality assessment. Non-wis2box users should ensure that the metadata record passes the pywcmp ETS validation before publishing; see https://github.com/World-Meteorological-Organization/pywcmp. Data publishers using wis2box should ensure they use the latest version of the wis2box software to ensure the latest version of pywcmp is used.

|===

[NOTE]
.Implementation note regarding wis2box and metadata management
====
`wis2box` reduces metadata-related issues by enforcing a "dataset-driven workflow".

- Before publishing any data notifications, a dataset must first be created
- To create a dataset, a minimum amount of information must be provided to create the WCMP2-record
- Before publishing the WCMP2-record, the content is always validated using pywcmp
- Data notifications are associated to metadata programmatically by querying a local copy of the published WCMP2-records

WIS2 Node implementations that use separate software for metadata and data notifications are more likely to encounter metadata related issues.

To reduce these issues, follow a wis2box-like workflow: create the metadata record first, then publish data notifications based on the published metadata records for your WIS2 Node.
====
